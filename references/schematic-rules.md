# 原理图与电气规则

## 设计依据

- 使用具体型号、封装和数据手册版本；建立 LCSC ID、器件 UUID、libraryUuid、符号和封装对应关系。
- 查询多匹配结果时核实精确型号与封装，不默认选择第一项；缺少 libraryUuid 时查库获得，不编造。
- 用实际引脚号建立连接表，不依赖符号位置、引脚名称相似或另一型号参考电路。
- 显示必要的位号、值/型号、极性、接口功能、电压域；保留 BOM 完整参数。
- 让电源→处理→输出的阅读顺序清晰；用有标题的透明模块框和合理留白，避免装饰影响可读性。

## 电气审核

| 项目 | 必须核实 |
| --- | --- |
| 电源 | 电压范围、峰值负载、稳压器压差、额定功率、反接/回灌、保护需求 |
| 稳压器/DC-DC | 数据手册要求的输入输出电容、ESR、反馈补偿、使能和热耗散 |
| MCU/模块 | 每个供电脚、地脚、裸露焊盘、复位、启动配置、下载接口、保留/禁用脚 |
| 去耦 | 每个要求的供电脚/域的电容、额定电压、直流偏压与数据手册约束 |
| IO | 逻辑电平、电压容限、方向、开漏上拉、驱动能力及复用冲突 |
| 晶振 | 频率、负载电容、ESR、驱动限制；不要把晶体标称负载电容直接当外接电容 |
| USB/总线 | 接法、收发方向、端接/串阻、上拉、ESD 与实际接口模式要求 |
| USB-C | 根据电源/数据角色核对 CC，不能给所有角色照抄固定电阻方案 |
| 连接器/开关 | 视图方向、引脚号、内部短接关系、屏蔽外壳与系统地策略 |
| NC/特殊焊盘 | 按资料区分必须接地的 EP、可悬空脚、机械脚与真正 NC |
| 极性与额定值 | 二极管、电解/钽电容、LED、MOSFET 栅源漏及瞬态额定值 |

不可因引脚未出现在映射表就跳过 EP 或地脚。四脚轻触开关的同极脚必须同网；
具体内部导通组合以所选型号资料/实测为准，不推广示例脚号。

## 图纸规格与多页组织

- 不强制把所有电路挤进单张 A4。A4 放不下时，可在同一工程/目标板下拆成多张原理图，或改用 A3、A2 等当前 EDA 支持的更大图纸；两种方式可以组合。
- 优先保持已有合适的图纸规格；新建或容量不足时，按模块数量、模块完整性、阅读和输出用途选择纸张、方向及页数，不设置固定的放大/拆页先后顺序。
- 模块之间联系紧密且适合整体阅读时可扩大纸张；独立功能模块较多时可分到多页。避免无必要地把一个完整功能电路拆散。
- 保留合理字体、元件间距和留白，不靠缩小元件/文字、重叠或取消必要标注来适配 A4。
- 在线操作时通过当前 API 或可用 UI 实际设置图纸大小、横竖方向和图框，并读回确认；仅改变缩放、打印适配或画图框不等于修改了图纸规格。离线时列明计划使用的规格和页数。
- 元件、导线、标签、模块标题和注释必须位于有效图框内，避开标题栏及边界；改纸张或拆页后重新检查排版。
- 多页图纸设置清楚的页名、页码/总页数及标题，所有图页中的元件位号保持全工程唯一。
- 跨页连接使用工程支持的全局网络或层次端口，核实作用域、端口对应和网络名；必要时标明目标页，不能仅凭不同页上文字同名就认为电气相连。
- 拆页、迁移或改图纸后，核对整个目标工程的实际网表并执行全工程 ERC，确认网络与器件没有遗漏、重复或意外合并。
- 导出/打印预览按所选图纸逐页检查字号、裁切、图框和标题栏；不要将 A3/A2 强制缩印到 A4 后仍以原有可读性宣称验收通过。

## 元件布局和连线

- 先读取符号边界框，再算元件、位号、值和标签的占用范围，不把经验间距当碰撞检测。
- 原理图坐标通常为 10 mil/单位；网格、引脚和导线端点必须对齐。
- 参考间距：R/C 横向约 100 单位、小 IC 约 200、较大器件约 350–400；按边界框调整。
- 模块框预留约 100 单位内边距；使用透明填充，避免遮盖内容。
- 模块内 R/C/反馈优先直接连线；跨模块网络使用唯一、可理解的网络名。
- 确认标签的局部/全局/层次作用域；同名标签是否连接以实际网表为准。
- 保留输入/输出/双向/开漏等电气语义；端口图形不是芯片引脚电气类型的替代品。
- 端点必须真实吸附；交叉与相交点区分清楚，不靠视觉接近判断连通。
- 对确认为 NC 的引脚放置不连接标记；禁用脚按资料处理，不能一律悬空。

## 密集引脚的可选扇出

读取 `sch_PrimitiveComponent.getAllPinsByPrimitiveId()` 后，按已审核映射创建电源标记、地标记或信号端口。
标签与引脚端点起始间隔可取 10 原理图单位；空间不足时扩展并重新检查。

上游常用方向偏移为 `0:(+10,0)`、`180:(-10,0)`、`270:(0,-10)`、`90:(0,+10)`。
它与“Y 向上”的直观方向命名存在易混处；先在当前符号/旋转状态验证一个引脚的实际端点和向外方向，
再批量应用。旋转、镜像、库符号差异不得凭常量猜测。

若当前 API 文档与运行时一致，使用 `createNetFlag("Power", ...)`、
`createNetFlag("Ground", ...)` 或方向合适的 `createNetPort(...)`，再创建连接短线。
不要统一把所有信号设为 BI 并据此宣称方向校验通过。

## 修改与转 PCB

- 先记录目标元件关联的标签、导线和实际连接；修改后清理自己生成的孤立对象。
- 优先用持久 ID/归属记录；仅按邻近坐标删除容易误伤相邻元件，不得直接批量删整个矩形内对象。
- 用 `toAsync()`、修改状态、`await done()` 的当前有效写法；重读实际结果。
- 等待全局网络刷新，再导出/读取实际网表；不能仅统计“每个引脚一条线”的数量。
- 执行 ERC，逐条处理或解释警告，不修改引脚类型或忽略规则以掩盖短路。
- 转 PCB 前核对每个符号脚到封装焊盘映射、位号唯一性、BOM/装配版本、封装和网络。
- 使用项目支持的 ECO/更新 PCB 流程，审查差异；保留已有布局、走线与锁定状态。
- 同步能携带的 PCB 规则；对未携带的规则在 PCB 中补设并读回。
